Task 5 — ليه QueryClient و Provider و useState وجوه body
المكان في الاستاك: Next.js App Router + TanStack Query
مرتبط بـ: Task 5 (useLeads) — مش شغل الـ hook نفسه، شغل الدرج اللي الـ hook بيستعمله

==================================================
المشكلة
==================================================

useQuery مش بيخزّن الداتا جوه الكومبوننت. محتاج درج مشترك: الكاش، isPending، isError، وإعادة الجلب.

من غير الدرج ده، كل استدعاء لـ useQuery تايه: مفيش كاش، ومفيش حالة تحميل مفهومة على مستوى الأبلكيشن.

الأدوار — مش نفس الحاجة:

- getLeads = تروح المخزن تجيب البضاعة (Supabase).
- useQuery = الموظف اللي بيسأل: البضاعة في الدرج ولا نروح نجيبها؟
- QueryClient = الدرج نفسه (الكاش).
- QueryClientProvider = اللي بيقول لكل الموظفين: الدرج هو ده.

useLeads بيستخدم الدرج. Provider بيخلقه. الاتنين مش بديل لبعض.

==================================================
ليه ملف Provider.tsx لوحده
==================================================

layout.tsx لازم يفضل Server Component:
- metadata (عنوان التاب) بيشتغل في السيرفر بس.
- الـ layout مش المفروض يبقى كلاينت عشان شوية context.

QueryClientProvider و useState شغّالين في البراوزر. لو حطيتهم في layout:
- يا إما تكسر الحدود،
- يا إما تحط "use client" على الـ layout كله وتضيّع فايدة السيرفر وmetadata.

عشان كده الاتنين:
- layout (سيرفر) يستدعي Provider (كلاينت) زي ما بيستدعي Toaster.
- Provider مش صفحة. ده غلاف حوالين كل الصفحات عشان أي كومبوننت بعدين ينادي useLeads يلاقي الدرج.

==================================================
ليه useState(() => new QueryClient())
==================================================

المشكلة مش «React بيحب useState». المشكلة: مين بيخلق الدرج، وكم مرة.

لو كتبت فوق الملف:
const queryClient = new QueryClient();

السطر ده بيشتغل لما الـ module يتحمّل. على السيرفر، الملف ممكن يفضل محمل لناس كتير ورا بعض. درج واحد → كاش مشترك بين زوّار. حتى لو إنت المستخدم الوحيد دلوقتي، النمط غلط من أول يوم.

كمان: من غير "use client"، Provider يفضل Server Component وبيدي queryClient كـ prop لـ QueryClientProvider. Next مش بيقدر يبعت علبة حية من السيرفر للبراوزر. العلبة لازم تتخلق في الكلاينت.

useState(() => new QueryClient()) بتقول:
- اخلق الدرج جوه كومبوننت الكلاينت، أول ما التاب يترندر.
- احتفظ بنفس الدرج طول ما التاب مفتوح.
- مش درج جديد كل رندر (عشان كده useState هنا مش قيمة بتتحدث؛ بتثبّت العلبة).

الدالة () => new QueryClient() مش القيمة نفسها: React بيناديها مرة في الأول، والنتيجة تتقفل في الـ state.

==================================================
ليه جوه body مش برّاه
==================================================

شكل HTML الثابت: html جواه body، وجوه الـ body المحتوى.

QueryClientProvider غالبًا مش بيطلع تاج في الصفحة (مفيش div زيادة). لو لفّيته حوالين body، تبقى حاطط حاجة React بين html و body. ساعات تعدّي، وساعات تبوظ الـ markup أو تطلع تحذير.

جوه body هو المكان الطبيعي لأي غلاف تطبيق (Toaster، الـ provider، الصفحات). الأثاث جوه الشقة، مش بين باب العمارة وباب الشقة.

==================================================
إزاي تستخدمه (باختصار)
==================================================

ملف كلاينت: src/app/Provider.tsx
- "use client" فوق.
- useState(() => new QueryClient()).
- QueryClientProvider يلفّ children.

layout.tsx يفضل سيرفر، ويستورد Provider جوه body جنب Toaster.

بعدها useLeads يقدر ينادي useQuery. الـ queryKey ["leads"] هو اسم الدرج للـ leads. الفلتر قرار عرض في الـ hook، مش كويري جديد.

==================================================
بدائل — امتى أنهي
==================================================

- "use client" على layout كله: يشتغل الـ provider، وmetadata تروح. زيادة من غير فايدة.
- const queryClient فوق الملف حتى بعد "use client": على السيرفر أثناء الـ SSR نفس مشكلة الدرج المشترك.
- new QueryClient() جوه الرندر من غير useState: درج جديد كل رندر → الكاش بيتصفر، وممكن refetch يتكرر.
- من غير Provider: useQuery مالوش درج. مش بديل.

الرسمي عند الحجم ده: Provider كلاينت صغير + useState + جوه body.

==================================================
دليل شفناه في المشروع
==================================================

أول نسخة: QueryClient اتعمل فوق layout.tsx (سيرفر) واتلف حوالين body. بعد النقل لـ Provider.tsx من غير "use client" ومن غير useState، نفس المرض اتنقل للملف الجديد. اللي صلّح: "use client" + useState(() => new QueryClient()) + Provider جوه body.
